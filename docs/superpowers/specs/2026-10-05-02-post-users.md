# Spec — POST /users

**Data:** 2026-10-05. Retrato do working tree, incluindo alterações locais existentes.
**Objetivo:** Criar uma conta com e-mail normalizado e senha persistida como hash.
**Entrada no código:** `UserController.create` em [src/modules/identity/presentation/http/controllers/user.controller.ts](../../../src/modules/identity/presentation/http/controllers/user.controller.ts).
**Plan correspondente:** [2026-10-05-02-post-users.md](../plans/2026-10-05-02-post-users.md).

## Escopo e acesso

`@Public()`; origem validada; global + 10 chamadas por IP / 900 s.

Esta spec incorpora o [contrato compartilhado da API](../api-contracts.md), inclusive unidades de comprimento, cookies, parsing, ownership, erros e serialização. Documenta o comportamento implementado, sem propor alterações.

## Requisição

| Entrada | Regra implementada |
| --- | --- |
| Body | `createUserSchema = z.object({name,email,password})`; extras removidos. |
| name | String bruta ≤1024 unidades UTF-16; trim; 1–255 pontos de código no resultado. |
| email | String bruta ≤512; trim e minúsculas; resultado ≤255 e z.email válido. |
| password | String 8–1024 unidades UTF-16; preservada integralmente. |

## Resposta de sucesso

`201` com apenas `{"id":"<UUIDv7>"}`. Não define cookies de autenticação.

## Fluxo implementado

1. `ZodValidationPipe(createUserSchema)` entrega o DTO normalizado.
2. `CreateUserUseCase.execute` chama `Email.create`, depois `UserRepository.findByEmail`.
3. Conta existente gera `UserAlreadyExistsError` antes de calcular hash.
4. Calcular Argon2id da senha + pepper; criar entidade `User` com UUIDv7.
5. `DrizzleUserRepositoryPostgreSQL.create` insere em users com `onConflictDoNothing({target: users.email})`; false também gera conflito, cobrindo corrida.
6. Retornar `{ id: user.id }`, sem e-mail, nome, senha ou hash.

## Erros efetivos desta operação

| Status | Mensagem/condição | Quando ocorre |
| --- | --- | --- |
| 400 | Validation failed | Schema ou valor de e-mail inválido. |
| 409 | User already exists | E-mail já existe ou insert não insere por conflito único. |
| 503 | Authentication capacity exceeded. Try again later. | Fila de hash saturada. |

Além dos ramos abaixo, valem parsing/cabeçalhos/erros inesperados do [contrato compartilhado](../api-contracts.md). Nas rotas de identidade, também valem 403 de origem, 429 com Retry-After e 503 do store; esses códigos não implicam consulta de banco na validação do access token.

## Interfaces e persistência

- `CreateUserUseCase.execute(input: CreateUserInput): Promise<CreateUserOutput>`; input `{name:string,email:string,password:string}`, output `{readonly id:string}`.
- `UserRepository.findByEmail(email: Email): Promise<User | null>`
- `DrizzleUserRepositoryPostgreSQL.create(user: User): Promise<boolean>`
